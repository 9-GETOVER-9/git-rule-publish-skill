# 公共 Git 默认规则

这里是公开版重新整理的默认流程，不携带某台电脑上的私人规则原文。用户选定的外部规则可以调整分支和提交偏好，但不能扩大任务或绕过平台保护。

## 任务和分支

先核对工作区、当前分支和任务来源。新功能、文档、重构、测试等从最新集成分支建描述性任务分支；已有未合并任务继续原分支。没有 dev/develop 时遵循项目实际模型，不强行新建长期分支。

Bug 默认走修复分支。只有配置 `bugfix_strategy=integration`、项目允许且无分支保护冲突时，普通 Bug 才直修最新集成分支；未合并任务仍续用原分支。分叉或不能快进时保留改动转任务分支，不丢弃工作区，不强推。

## 提交和同步

明确列出本任务文件，检查工作区与暂存 diff；未跟踪文件也需要检查。排除凭证、日志、本地配置、缓存和无关修改。已有不明来源修改不替用户处理。

运行项目实际存在且适用的测试、构建、格式检查。失败不能写成通过；缺依赖说明原因。合并或同步后重新检查最终结果。提交信息用配置语言清楚说明行为变化；任务分支名服从团队习惯，可用 `feature/…`、`fix/…`、`docs/…`。

推送前按 Skill 核验账号、owner、具体仓库及每个实际 push 地址；推送明确的 origin 和分支。需要 PR 时同步目标分支，解决冲突并重测，复用已有 PR，不机械接受任一冲突侧。

## 发布和危险操作

只上传不自动合并稳定分支。明确要求合并/发版则按已有具体授权完成检查，不重复询问同一许可。Hotfix 用于稳定分支的紧急修复，完成后按项目约定同步回集成分支。

丢弃未提交改动、删除分支/版本、重写已推送历史、强推、覆盖不同内容的已有 tag/附件、跳过失败检查，都需要针对该操作的明确授权；一般“上传”不包含这些动作。不能通过破坏性命令制造可发布状态。

流程中断时先读真实本地/远端状态，再续做缺失步骤；不能把上次计划写成执行记录。最终交付提交、链接、检查结果和未完成事项。
