# 目标校验与发布动作

## 推送前的实际目标

脚本 `scripts/check_push_target.py` 使用当前 Git 配置解析 `origin` 的 fetch URL 和 `git remote get-url --push --all origin`，核对 Git URL 重写后的所有目的地。所有者取自用户选定配置的 `target_owner`，并匹配本次确定的具体仓库；同一 owner 下的两个仓库也不能混淆。脚本不会输出原始 URL、凭证或 Git 错误正文。

自动通过范围限于 `https://github.com/<配置的OWNER>/<目标仓库>`（可带 `.git`）。带用户信息、查询、片段、非默认端口、未知协议、本地路径等都不通过。不把参数传入 shell，不用命令输出拼接 shell 命令。运行时超时是本地元数据命令的保护，不是平台故障结论。

SSH 地址或别名返回“需要额外核验”。此时先只读检查实际 SSH 主机、端口、用户名、Include/Match、ProxyCommand/ProxyJump 和身份配置；不能只看别名中的 github 字样。`ssh -G` 也可能触发 Match exec，不在未检查配置时盲跑。不能可靠确认实际目的地和身份时暂停推送，不绕过失败或擅自改成另一账号。已明确授权且已逐项核验的 SSH 可按核验记录继续，脚本本身仍不宣称 SSH 检查通过。

核对 HTTPS 的 Git 凭证身份与 `gh` 身份可能不同；使用当前可信凭证管理方式，不打印凭证。不通过 `git credential fill` 输出 token 来检查。遇鉴权失败应报告，不换账号、不反复盲重试。实际推送明确为 `git push origin <当前分支>`，首次可加 `-u`；禁止用 URL 参数或 `git -c` 改写检查后的目的地。配置、远程或分支改变后重新核验。需要显式 refspec 时同时核对目标分支，不能借 refspec 删除或强制改写远端。

## 授权范围

| 用户请求 | 完成的动作 | 不自动附带的动作 |
|---|---|---|
| 上传当前成果 | 检查、暂存本任务、提交、推送；项目流程需要时建/更新 PR | 合并稳定分支、打标签、Release |
| 创建/更新 PR | 前述步骤及准确的源分支、目标分支、描述、链接 | 合并 PR |
| 合并指定 PR | 检查 PR 身份、目标、最终 head SHA 的测试及保护要求后合并 | 绕过保护、忽略失败检查、删除无关分支 |
| 发布新版本/带安装包的 Release | 选版本、准备变更说明、验证目标提交、打包和校验、创建标签/Release、上传附件并核对结果 | 未授权的仓库可见性变更、覆盖现有版本或强改标签 |

明确要求发版包含完成该版本所必需、符合既有分支约定的正常合入；不能因“不要自动合并”而重复索要这次已经给过的授权。若待合入还有其他任务、存在失败测试或目标不明，先把本次可审查结果准备好，再只问缺少的决定。新仓库已明确 Public/Private 不再追问。

## 最终提交、附件与恢复

- 本地检查记录命令和提交；修改/同步后旧检查不能冒充最终版本通过。需要 CI 时看准确 head SHA 的运行和结论；没有 CI 如实说明。没有流水线不伪造通过，也不为了上传临时绕过仓库要求。
- 发版前确认工作区、版本文件、标签提交与包内容相符；从清晰的目标提交构建，运行项目适用的安装/解包检查，生成附件 SHA-256。使用项目现有打包脚本，不把缓存、日志、凭证或课程数据混入包。
- 创建 Release 后核对 URL、tag、目标提交、附件名称/大小/摘要。中断恢复先查询现有标签、Release 和附件；同版本已有不同内容时停止覆盖，说明差异。相同内容续做缺失步骤，不重复发版。
- 多行 PR/Release 描述优先结构化工具参数；使用 gh 时将文本写入本任务临时 UTF-8 文件并传 `--body-file`。不把 Markdown、反引号或用户输入拼成 shell 代码。
- 凭证、私有 URL、工作目录和测试日志中的敏感内容先脱敏。公开 PR/Release 仅放项目必要信息；用户允许本地读取的私人材料不自动获得公开上传权限。
